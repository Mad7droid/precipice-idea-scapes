Precipice / Product experience

Scapi.
The copilot’s UX, in detail.

How people ask questions, explore their canvas, make changes, follow the work, and stay in control.

Implementation snapshot · 7 October 2026 · Repository revision 7dc6f83
Audience: product, design, engineering, research, and stakeholders.

How to read this document. This is an inventory of the current implementation, not a future feature specification. Implemented denotes behavior enforced in code. Model guidance denotes a requested response style, which is not guaranteed. Current caveat identifies mismatches or limits visible in the source.

Illustrations below are simplified explanatory examples, not product screenshots. No real user content is included. The HTML is self-contained and can be shared or opened offline.

01 / EXPERIENCE MODEL

A canvas copilot with two kinds of intent

Scapi lives inside Precipice, a visual workspace made of objects and directed relationships. The core experience separates understanding the work from changing the work, while keeping both available through one composer. The canvas remains the working artifact; the conversation helps people interpret or transform it.

Ask

Understand the canvas

Ask questions, identify gaps, compare objects, find connections, and optionally research the web. Responses appear as text. Ask has no document mutation tools.

Edit

Change the canvas

Describe an outcome. A generator creates, updates, deletes, renames, or connects content as validated actions arrive. The user sees the result on the canvas and a receipt of applied actions.

The recurring UX patterns

  • Explicit intent: an Ask / Edit segmented control names the consequence before submission.
  • One draft across surfaces: the canvas composer and side panel share the same text, mode, and settings.
  • Results where the request began: canvas questions receive an inline answer; panel questions receive a transcript; edits materialize on the canvas.
  • Progressive disclosure: approach, work details, generation steps, and skipped actions are available without dominating the result.
  • Contextual assistance: current objects, selection, relationships, and starter type shape the request.
  • Reversible execution: generation changes share a transaction; Stop preserves applied work and Undo can reverse it.
  • Explicit trust boundaries: Ask cannot write, selection limits Edit’s targets, and invalid generation actions are rejected.

Evidence: src/app/Editor.tsx, src/ai/Composer.tsx, src/ai/scapi/scapiTools.ts, src/ai/generate.ts.

03 / SPATIAL PATTERNS

Two surfaces, one conversation state

The canvas composer

A compact launcher sits at the bottom of the canvas. Activating it expands the full composer and focuses the input. The expanded composer and result surfaces have a maximum width of 720px. The canvas bar is hidden while the Scapi panel is open, so the user does not see two simultaneous editors for one draft.

Asking from the canvas keeps the panel closed and shows the latest answer above the composer. This preview scrolls within a maximum height of 38vh. “Open in Scapi” reveals the richer transcript. “Dismiss answer” hides this preview without deleting the conversation. Only the latest canvas-origin turn appears here.

Editing from the canvas keeps attention on the changed objects. The Ribbon appears above the composer. When generation reaches the done state, the full canvas composer collapses back into its compact launcher.

The Scapi side panel

The panel occupies the right-side region that otherwise hosts the inspector. It contains a header, optional proposal review, scrollable transcript with generation activity, and a fixed composer footer. The transcript is lazy-loaded on demand.

Header action Behavior
Expand / Narrow Switches between min(420px, 65vw) and min(720px, 92vw). The wider state makes longer answers easier to read.
Clear Aborts an Ask request and removes Ask transcript and model history. Disabled when there are no Ask turns. It does not undo canvas edits.
Close Hides the panel. A running Ask or Edit continues. Reopening reveals the current state.

Entry points

The editor exposes Scapi in the top bar, the command palette (“Ask Scapi” / “Close Scapi”), and the keyboard shortcut ⌘/Ctrl J. “Open in Scapi” is the escalation path from a short canvas answer to the full conversation. The command palette can also expand and focus the canvas composer.

Evidence: Editor.tsx, including shared state, keyboard handler, canvas answer preview, and right-panel rendering.

04 / INPUT

A shared, multiline, mode-aware composer

Illustrative UI · Ask mode
What is missing from this onboarding flow?

  • Multiline first: Enter inserts a newline. Command+Enter or Control+Enter sends. The shortcut hint is shown when space allows.
  • Auto-growing input: the text area grows with the draft up to 168px, then scrolls internally.
  • Focus as a container state: focusing the input emphasizes the composer border and shadow, rather than drawing a separate inner field.
  • Submission guard: a blank or whitespace-only prompt cannot be sent. Requests are trimmed before submission.
  • Draft continuity: changing mode or opening/closing the panel preserves the shared draft. In the current editor, the controlled draft is also retained after sending; the generic uncontrolled composer clears its own local value.
  • Busy state: Send becomes a neutral square Stop control, with a working indicator. Mode, scope, model, and relevant configuration controls are disabled for the active request.
  • Follow-up drafting: while the same mode is working, the text field can remain editable, but submission is blocked. Switching away from the busy mode is disabled through its mode control.
  • Adaptive placeholder: Ask about this scape / selection; describe a change to this selection; or the starter-specific Edit prompt.

Availability and credentials

The panel’s composer is disabled without a key and says “Add an API key in settings to ask.” The canvas composer can reach the key guard, which reports “No API key” and opens Settings. Normal Ask and Edit submissions are also blocked when the tab does not hold the editing lease—even though Ask itself does not mutate the document.

05 / CONTEXT

Selection provides focus; Edit scope provides a boundary

When objects are selected, scope defaults to Selection. With no selection, it defaults to Whole scape. A user override is associated with the exact selected IDs; changing the selection recalculates the default. The Selection option includes the current object count and is only offered when something is selected.

Ask: selection is a relevance hint

At send time, Scapi reads the current canvas and current selection. Selected objects are named in the question context, with guidance to treat the question as about those objects unless the question clearly says otherwise. The full canvas projection is still supplied.

No explicit pinning or @mention picker is implemented in the inspected composer. The internal “pinned” field currently captures selection.

Edit: selection restricts action targets

The apply layer permits changes to selected existing objects and objects created during that generation. It rejects updates or deletions targeting other existing objects, connections to outside endpoints, removal of outside relationships, and scape renaming.

Creating supporting objects remains allowed. Selection scope is not a promise that object count or global layout will remain unchanged.

Current caveat Ask’s visible scope control is not passed into useScapi.send. Choosing Whole scape with objects still selected changes the placeholder but does not remove the selection hint from the Ask request. Edit does honor Whole scape in both prompt construction and action enforcement.

Context limits that affect expectations

Ask uses a roughly 12,000-token projection budget. Object bodies are capped at 1,200 characters each, with relationships allocated up to 20% of the budget. When content is too large, middle portions can be omitted while retaining both ends. Canvas search returns up to 12 matches; object reads accept up to eight IDs per call.

The object-read helper uses the same 1,200-character body renderer. Consequently, the activity phrase “reading … in full” should not be interpreted as a guarantee that arbitrarily long object bodies reach the model. Edit uses a smaller, roughly 4,000-token projection with detail concentrated around selected and nearby objects.

Evidence: Editor.tsx, useScapi.ts, scapiPrompt.ts, context.ts, scapiTools.ts, generate.ts.

06 / ASK JOURNEY

From an empty conversation to a grounded answer

Choose context→Write or choose a question→Read / reason / research→Stream answer→Follow up or act

Empty-state invitation

Ask about this scape.
Scapi can read every object on the canvas. Ask answers questions without changing your work. Choose Edit to make changes.

The empty state provides up to three question suggestions derived from the current document. They are action buttons: clicking one submits that question, rather than only filling the draft.

Canvas condition Candidate suggestion, in priority order
At least one unconnected object “Which objects aren't connected to anything?”
More than one wireframe “Compare the wireframes and explain the trade-offs.”
At least one object “What's missing from this scape?”
Always “Summarise the flow in five lines.”

Suggestions are deduplicated and capped at three, so the summary question can be displaced by the more contextual options. If an Edit activity ribbon is present, the standard empty conversation state is suppressed.

Turn anatomy

Each question is a right-aligned bubble capped at 85% of the available width. Beneath it, Scapi may show Approach, working activity, an intent label, the answer card, response actions, references, and an error or stopped state. Not every turn needs every element.

07 / RESPONSE DESIGN

The question determines the shape of the answer

Gen UI pattern · Adaptive content inside fixed components

In Ask, the model generates Markdown content and references. The application supplies the answer card, intent label, table wrapper, object chips, source list, and actions. The label is inferred from the question; it is not a model-generated component specification. This is a constrained, adaptive answer surface, not arbitrary generated HTML or an interactive app embedded in chat.

Model guidance Scapi is prompted to lead with the answer, avoid filler, use sentence case, and prefer short paragraphs or a few complete bullets. Ordinary replies are requested to stay under 120 words unless expansion or troubleshooting is requested. These are writing instructions, not a hard UI validator.

Intent / visible label Requested response structure
Summarize / Summary One direct sentence plus at most four bullets; group related objects; generally name no more than three object IDs.
Expand / Expanded More depth in short, useful headed sections.
Simplify / Simplified Plain words, short sentences, jargon defined in place.
Compare / Comparing Deciding difference first; a narrow two-column Aspect / Comparison table, or sections for three or more options.
Troubleshoot / Troubleshooting Most likely diagnosis, canvas evidence, smallest ordered resolution steps.
Suggest / Suggestions Recommended next move, then up to three prioritized suggestions tied to evidence.
Locate / Finding Relevant object IDs first, then a short reason for each.
How-to / Working through it A concise numbered procedure; prerequisites only when material.
Research / Researching Practical conclusion first, canvas facts distinguished from web findings, sources in their source block.
Direct / Scapi One or two sentences; up to three bullets only when useful.

Intent is inferred through ordered keyword rules on the question. It is a presentation hint, not a user-selected response template. A question matching multiple categories receives the first matching category; the body is still freeform Markdown.

Answer rendering

  • Markdown paragraphs, headings, lists, emphasis, quotes, links, code, and GFM tables render inside one bordered, raised answer card.
  • Markdown heading levels are normalized to the panel’s hierarchy; they do not become oversized page titles.
  • Tables sit inside a horizontal scroller with “Comparison” and “Scroll sideways to see all columns.” That wrapper appears for any rendered table, not only true comparisons.
  • Existing object IDs in code spans become clickable title chips. Unknown IDs remain styled code.
  • External answer links open in a new tab with noopener noreferrer.
  • Completed Markdown blocks are memoized; the active fragment can update without re-parsing the whole conversation.

Evidence: answerFormat.ts, scapiPrompt.ts, ScapiPanel.tsx, ObjectChip.tsx.

08 / WAITING & STREAMING

Make waiting legible, then let the answer take over

Approach and Working are separate disclosures

Approach contains provider-supplied summarized reasoning when it exists. Working contains an activity trail, its current step, and any available research references. Both initially expand before answer text appears and automatically collapse when the answer begins. The user can reopen them.

The working header changes from “Working…” to “Responding” once body text exists. Completed activity rows have checkmarks; the current row uses a 3×3 dot matrix. Before an activity exists, the label is “connecting.” After 700ms without a body or activity-length change, the label becomes “preparing the next part.” That timer indicates a pause in visible updates, not a measured backend phase.

Activity supported by the view Visible copy / source status
Canvas projection “reading the canvas: N objects”; emitted before the provider request.
Reasoning begins “thinking it through”; emitted on the first reasoning delta.
Canvas search “searching the canvas for ‘query’”; emitted by the read tool.
Object read “reading N objects in full”; emitted by the read tool, subject to body truncation.
Writing begins “writing the answer”; emitted on the first text delta.
Web search / source count UI supports search-query and “read N sources” events, but the inspected Ask stream adapter does not emit these event kinds. URL sources are handled separately.

Calm streaming

Incoming text is buffered and painted in readable pieces using animation frames. The implementation uses a 50ms minimum-paint interval in its buffering logic, a 120-character buffering threshold, and a 56-character per-paint target for suitable plain-text runs. These are heuristics, not a fixed-speed typewriter.

Incomplete links, inline code, fences, emphasis, and trailing table runs can be held until stable. Completion and Stop flush buffered content. A final cleanup removes some dangling emphasis and empty bullet syntax. Large unfinished Markdown structures can therefore delay visible text even while output is arriving.

Reading position belongs to the user

The transcript follows growth while the user is within 32px of the bottom. Scrolling upward stops automatic following. “Jump to latest” appears above the composer inside the transcript region; activating it returns to the bottom and resumes following. Browser scroll anchoring is disabled to avoid competing with this behavior.

After completion, meaningful activity becomes a compact summary such as canvas searches or objects read. A routine canvas-read-and-answer turn shows no extra summary. The live working disclosure is replaced; its full trail is not retained as a browsable finished disclosure.

Evidence: ScapiPanel.tsx, useScapi.ts, ask.ts, DotMatrix.tsx.

09 / EVIDENCE

Connect answers to objects and external sources

Object references are navigation

An object chip shows a colored dot for its type and the object’s current title, truncated when needed. Its tooltip includes title and ID. Clicking clears edge selection, selects the referenced object, and asks the canvas to focus it. It does not automatically close the conversation or edit the object.

Web search is optional

Search web is initially on. Ask can use the provider’s web search tool, with a maximum of three uses in an Ask run. The full Ask loop is limited to six model steps. Enabling search allows research; it does not guarantee that every question will trigger a search.

If an error is classified as web search being unavailable, Scapi retries without search and disables the toggle for the current hook session. The main shared composer explains the unavailable state in the control’s tooltip. The simpler fallback composer has a fuller message directing users to the Anthropic Console; that message is not rendered by the main editor’s injected composer.

Sources arrive independently of prose

URL source events are deduplicated by source ID. While working, sources can appear under Research before answer prose exists. Once an answer has finished and has a body, Sources appears below the actions. Each entry has a number, title, and hostname, and opens externally. There is no source-preview panel or citation-hover interaction in this implementation.

Trust pattern: Ask tools can search and read, but cannot call the document mutation path. Canvas data is framed as untrusted reference material in the prompt. This protects the document from direct Ask-side writes; it does not guarantee factual accuracy.

Evidence: ObjectChip.tsx, Editor.tsx, ask.ts, scapiTools.ts, ScapiPanel.tsx.

10 / TRANSITION TO ACTION

“Turn into an edit” creates a reviewable proposal

Completed Ask answer→Turn into an edit→Review before editing→Apply proposed edit→Live generation + Undo
  1. Choose an answer. A completed Ask turn with a body offers “Turn into an edit.” Cancelled or errored turns do not offer it.
  2. Stage the proposal. The editor combines the original question and complete answer into a generator request. No canvas mutation happens at this point.
  3. Review in place. A region above the transcript says “Review before editing,” shows the answer text in a scrollable area, and describes the current scope.
  4. Understand interpretation. The copy explicitly states: “The generator will interpret the proposal above. You can undo the result.” This is prose review, not an exact action diff.
  5. Apply or cancel. Apply validates the lease and key, clears the proposal, switches into the Edit execution path, and shows the generation Ribbon. Cancel only drops the staged proposal.

Changing selection or scope invalidates the staged proposal, preventing an old proposal from remaining staged under a changed target scope. Applying is disabled during an Ask or Edit stream and in a read-only tab.

The staged text is not itself an editable proposal field. To alter its substance, the user can ask a follow-up or compose a different Edit request. The generator also receives the current model choice, allowed types, scope, and standing instructions.

Evidence: Editor.tsx proposal state, selection/scope effect, review region, and onTurnIntoEdit; ScapiPanel.tsx response actions.

11 / EXECUTION

Edit makes its result visible as it happens

Gen UI pattern · Structured objects rendered by the product

Edit generates typed object data through a fixed tool vocabulary. Registered renderers turn that data into native canvas cards. The model chooses content and supported structure; the application owns component code, validation, editing controls, and canvas layout. Generated objects remain ordinary document content that people can inspect and refine.

Generated wireframes: bounded visual composition

Wireframes are low-fidelity screen representations built from 13 supported primitives: section, heading, text, box, image, avatar, input, button, checkbox, toggle, badge, list, and divider. They use a 4-, 6-, or 12-column grid, defaulting to 12. Primitives can carry labels, spans, alignment, and applicable size hints; section headers span the full row.

Labels make the screen meaningful at a glance. Missing text can render as placeholder bars; images are placeholder graphics. Input, button, checkbox, and toggle shapes are presentational elements inside the wireframe, not working form controls. Scapi does not generate executable screen behavior, arbitrary components, or deployed applications through this path.

People can refine the generated wireframe through its inspector, including content primitives and layout settings. A generated note exposes editable title/body fields, a journey shows step labels and details, and a document block separates selecting the card from entering text editing. This keeps the AI result connected to the product’s normal editing model.

Additional Gen UI evidence: src/objects/wireframe/schema.ts, src/objects/wireframe/Body.tsx, src/objects/wireframe/Inspector.tsx, and Body.tsx in the note, journey, and scape object folders.

Direct Edit submission begins execution immediately. Model tool calls are validated, applied to the document, and announced one at a time. There is no “accept all” stage at the end. The same transaction ID groups the generation’s actions for Undo.

Capability User-visible result
Create object Adds a supported object with title, body data, optional tags and accent. The engine assigns layout.
Update object Changes supplied fields such as title, data, tags, or accent. Empty tags/accent can clear those marks.
Delete object Removes the object and its attached relationships.
Connect objects Creates a directed relationship between existing endpoints, optionally labeled.
Disconnect objects Removes a relationship by ID.
Rename scape Changes the document title, subject to scope rules.

There is no generator MoveObject tool and no coordinate input on CreateObject. Layout is an application responsibility. Once objects have been created, layout can run every third applied action and again at completion.

The generation Ribbon

  • Before the first action: a dot matrix accompanies time-based phrases: “Reading the scape…”, “Planning the shape…”, “Writing objects…”, advancing every 2.6 seconds. These are waiting copy, not provider-reported milestones.
  • During generation: an ordered, auto-scrolling list shows applied actions, capped at 132px tall, with action count, optional skipped count, and Stop.
  • Friendly receipts: creation can read “Added note: …”; a title update can read “Renamed block to …”. Other actions may retain an action-name prefix.
  • After completion: a single action can use its descriptive line; multiple actions show “N changes applied.” Expandable steps, model ID, skipped details, Undo, and Dismiss remain available.
  • Skipped actions: a bounded, scrollable panel gives tool name, short subject if available, and rejection reason. It does not dump the raw action payload into the UI.

In the side panel, the current Ribbon is appended after the Ask turns and scrolls with the transcript. It is not a persisted Edit message per generation: a later generation replaces the current generation state.

Evidence: tools.ts, generate.ts, useGeneration.ts, Ribbon.tsx, Editor.tsx.

12 / CONFIGURATION

Constraints are close to the prompt, details stay tucked away

Object-type picker

Edit exposes a pill whose label summarizes the permitted creation types. The menu uses checkboxes and filters its choices through the current starter. An unconstrained generic canvas shows “All types”; a constrained starter shows its actual available type names. A partial selection uses joined type names.

Internally, an empty selection means all available types. Turning on all types, or unticking the last type, returns to that unconstrained state. The menu closes on outside click or Escape. Excluded creation types are rejected at the apply layer as well as discouraged by the prompt.

Standing instructions

Edit’s Instructions pill opens a popover titled “How AI should work in this scape.” An accent dot signals nonempty scape instructions. The field includes an example about British English, short notes, and leading with risk. A remaining-character counter appears only in the final quarter of the limit.

  • Clicking away or closing with the pill commits the draft as one document change.
  • Escape abandons the draft.
  • Saving or clearing produces a confirmation toast.
  • Scape instructions are saved with the document and travel with its exported document content.
  • Global instructions come from Settings. The popover indicates whether they exist and offers “Edit those,” which commits the local draft and opens Settings.
  • The generation hook applies both global and scape instructions to normal generation and connection generation.

Current boundary These standing instructions are generation inputs. Ask hides the Instructions control and does not add these instruction fields to its system prompt.

Model selection

The same model preference is shared by Ask and Edit and disabled during the active request. The repository’s catalog at this revision labels its options Sonnet 5, Sonnet 5.5, Opus 5, and Opus 5.5, defaulting to the first. This documents local UI configuration; it does not verify external availability, pricing, or model claims in catalog hints.

Evidence: Composer.tsx, Instructions.tsx, useGeneration.ts, models.ts, Editor.tsx.

13 / CONTEXTUAL ACCELERATORS

Small actions translate selection into an immediate request

Action Intent and implementation
Connect this / Connect these Available beside the compact canvas composer when objects are selected and Edit is not streaming. Requests connections between those objects and the rest of the scape.
Expand Submits a predefined Edit brief asking for missing detail and connections around the selected object(s). Uses the normal Edit path and current scope.
Connect loose objects The outline can invoke connection generation for supplied IDs. The generator prioritizes relationships missing from the graph.

Connection generation exposes only ConnectObjects and DisconnectObjects. It cannot create, rename, update, or delete objects. It runs with Whole scape scope so it can connect selected objects to the broader graph. It requires at least two objects in the document; otherwise it reports “Not enough to connect” and asks the user to add another object.

Despite the language of “suggest” in some paths, connection generation applies relationships live. It is not an uncommitted proposal list. Its output shares one undo transaction.

Evidence: Editor.tsx contextual actions and outline callback, useGeneration.ts connect, tools.ts, prompt.ts.

14 / CONTROL & RECOVERY

Stop, hide, dismiss, clear, and undo are different actions

Action What changes What remains
Stop Ask Aborts the stream; flushes buffered output; marks the turn cancelled. Partial answer stays visible with “stopped.” It is not added to model history.
Stop Edit Aborts remaining generation. Already-applied changes stay and remain grouped for Undo. The Ribbon uses the done presentation, not a special stopped label.
Close Scapi Hides the panel. Requests keep running; draft and conversation state remain.
Dismiss answer Hides the latest canvas answer preview. The Ask turn remains in the panel transcript.
Dismiss Ribbon Clears the current generation UI state. Applied document changes remain.
Clear Aborts Ask and removes transcript and model context. Canvas content and generation changes remain.
Undo generation Reverses the generation if its transaction is still at the top of the undo stack. If later work exists, nothing is reversed and the app explains that something else changed.

Answer actions

Copy writes the raw Markdown body to the clipboard, then shows “Copied” for 1.4 seconds. Clipboard failure leaves the button unchanged. Retry is wired only to the latest non-streaming turn and replaces that display turn with a fresh request for the same question. It reads the current canvas, selection, model, and search state again.

The response-action row is nested under a nonempty body. A failed response with no body therefore has an error card but no visible Retry button. A completed turn’s provider history is not removed when Retry replaces its display card, so the previous successful exchange can still be part of model context.

Error vocabulary

Failure Message / next step
Missing key “No API key” · Add an Anthropic API key in settings.
Authentication “Scapi could not connect” · Check the API key.
Rate limit “Scapi is temporarily busy” · Wait a moment and retry.
Unavailable model “Model unavailable” · Choose a supported model.
Provider overload “Scapi is temporarily busy” · Try again in a few seconds.
Network “Could not reach Anthropic” · Check the connection.
Unknown provider failure “Something went wrong” · Response could not complete; try again.
Ask could not initialize “Scapi could not start” · Last-resort startup failure path can display the caught error detail.

Ask errors use an inline alert, preserving any partial text. Generation errors use a failed Ribbon with Dismiss. Partially applied edits are not rolled back automatically; the error Ribbon does not expose its own Undo control, so standard document Undo is the available recovery path.

A rejected internal provider tool history can trigger one retry with fresh model context, provided no answer text has appeared. The visible transcript is retained, but no dedicated history-reset notice is surfaced for this recovery.

Evidence: useScapi.ts, reducer.ts, ScapiPanel.tsx, useGeneration.ts, Ribbon.tsx, provider.ts, ask.ts.

15 / CONTINUITY

Visible history and model memory are deliberately different

State Lifetime and consequence
Ask display transcript Stored per scape in tab session storage. Up to the last 10 turns are persisted. Streaming turns are filtered out when restoring.
Provider conversation history Memory only. The last six complete exchanges are sent on follow-up requests. Questions and provider replies are kept together.
Cancelled / errored turns Can remain visible, but are excluded from completed model history.
Restored answers Shown with: “Earlier answers are shown for reference. This conversation starts fresh from here.” They do not recreate provider context.
Canvas snapshot Rebuilt at the start of every Ask. The prompt declares the current canvas authoritative over older conversation content.
Draft, mode, panel width Shared in editor component state. They survive surface switching, not a guaranteed full reload.
Search toggle / availability Hook state. Initially enabled / unknown; not persisted as transcript data.
Generation receipt Current hook state, replaced by later generations or Dismiss; not a durable multi-generation conversation log.

Storage failures do not block the live conversation. When saving hits quota, the implementation retries with fewer turns. The former Scapey storage key is migrated to the Scapi key when present.

Data and credential expectations

Local-first document storage does not mean AI runs locally. Ask and Edit send projected canvas content to the configured Anthropic model. In the browser, requests use the app’s proxy transport; desktop requests go directly to Anthropic. Browser credentials are session-scoped; desktop credential support can use macOS Keychain. Web research is provider-hosted when enabled.

The transcript uses tab-session storage, not a cross-device chat account. Do not describe it as permanent chat history or imply that reloading preserves conversational understanding.

Evidence: useScapi.ts, types.ts, ask.ts, scapiPrompt.ts, provider.ts, src/persistence/settings.ts, docs/security-and-local-data.md.

16 / VISUAL LANGUAGE

Quiet surfaces, a clear primary action, and compact evidence

  • Warm neutrals: the product token system uses an ash palette, with layered surface, raised, and inset backgrounds. Hairline borders separate regions without heavy framing.
  • Orange as action emphasis: the primary Ask/Edit button uses the strong accent. Selected mode is a softer treatment. Stop is neutral.
  • Rounded hierarchy: pill controls for compact settings, a large rounded composer, smaller rounded disclosures, and a raised answer card.
  • Typography by job: readable sans-serif for answers and prompts; monospace styling for activity, counts, and compact metadata. The app’s base text token, not a separate chat typography system, drives answer text.
  • Object colors carry type: note, journey, wireframe, and scape chips inherit type hues, connecting conversational references to the canvas vocabulary.
  • Bounded density: tables, proposal text, activity lists, and long inputs scroll within their own regions rather than forcing unrestricted page growth.

Existing motion behaviors

Product components use brief color/focus transitions, a width transition for the side region, grid-row and opacity transitions for disclosures, entry animation on suggestions and Ribbon lines, and a small dot-wave indicator. These emphasize state changes and ongoing work. The global reduced-motion rule reduces animation and transition duration to 1ms and limits animation iteration.

The dot matrix is accompanied by textual activity where supplied; users do not need to infer progress from the animation. Closing a disclosure reduces visual prominence while preserving access to its content.

Evidence: src/design/tokens.css, Composer.tsx, ScapiPanel.tsx, Ribbon.tsx, DotMatrix.tsx, Editor.tsx. This document describes existing motion; it does not add product animation.

The mode control uses a labeled group and aria-pressed. Disclosures expose aria-expanded. Icon actions have accessible names. The transcript has a visually hidden, polite, atomic live region that announces major status changes rather than every text token. Errors use an alert role. The proposal review is a labeled region.

Review needed The inspected Scapi panel does not implement a dedicated focus trap or explicit focus-return contract on close. The stopped state’s visible text is clearer than its generic live-status fallback. Source handling, horizontal table access, focus order, and small-screen behavior deserve interactive accessibility testing before claiming conformance.

19 / IMPLEMENTATION REALITY

Limits to communicate accurately

Gen UI boundary: Ask renders generated content inside fixed answer components. Edit renders validated object data through registered canvas components. Neither path currently produces arbitrary executable UI, custom chat widgets, live generated forms, or a runnable application from a wireframe.

These are observations from the implementation, not proposed features or a ranked defect backlog. They prevent the intended UX from being mistaken for guarantees that the code does not currently make.

Area Current reality / implication
Ask scope Whole scape does not suppress selected-object hints. Do not present Ask scope as a strict read boundary.
“Read in full” Object tool output remains capped at 1,200 body characters. Long-document completeness is not guaranteed.
Read-only tab Normal Ask is gated by the editing lease. Being read-only at the capability level does not mean it is available in a follower tab.
Selection side effects New objects are permitted; layout can reflow the canvas. Deleting a selected object also removes attached relationships, including relationships reaching outside selection.
Draft after send The editor retains the controlled draft. Do not demonstrate automatic draft clearing as a current behavior.
Canvas answer richness The inline preview is plain preformatted text. It does not render Markdown, sources, object chips, error details, Copy, or Retry; open Scapi for those.
Empty-body failure No response-action row means no Retry button on an answer that failed before producing body text.
Research trail The view supports web-query activity, but the stream adapter does not currently emit it. Sources can still arrive.
Search unavailable guidance The main composer offers a disabled toggle and tooltip; the fuller Console instruction belongs to the fallback composer.
Concurrency coverage Main Ask/Edit submission paths prevent overlap. The connection shortcut uses a separate path without the same Ask-streaming guard, so universal mutual exclusion should not be claimed.
Review fidelity Proposal review shows prose, not exact structured changes. The generator interprets it on Apply.
Edit transcript Only current generation activity is held. There is no durable sequence of Edit turns interleaved with Ask history.
Failure after partial Edit Changes remain, but the error Ribbon only exposes Dismiss. Standard Undo is needed.
History recovery Automatic provider-history reset does not announce loss of model context. Reload does show a restored-history notice.
Answer sizing Format-specific token preferences are all raised to at least 1,024 tokens for adaptive thinking. Shortness is chiefly prompt guidance, not a strict short-answer output cap.
Missing interaction families No implemented @mention selector, attachment upload, per-turn question editor, answer rating, chat-history browser, source preview, or exact Edit diff in these copilot surfaces.

Evidence: cross-check of rendered editor paths against useScapi.ts, ask.ts, context.ts, answerFormat.ts, generate.ts, and Ribbon.tsx.

20 / SHOWING THE EXPERIENCE

Five walkthroughs for a product review

Use a fictional canvas with two wireframes, several journey steps, and at least one unconnected note. Live answers and exact generated objects will vary with the model.

1. Understand before acting

  1. Open Scapi and choose a canvas-derived suggestion about missing content.
  2. Observe the question bubble, initial work state, and optional Approach.
  3. Read the recommendation and click an object reference to locate its evidence.
  4. Confirm the canvas content has not been edited.

2. Move from advice to an edit

  1. On a completed answer, select Turn into an edit.
  2. Review the proposal and scope copy.
  3. Apply it and watch the canvas changes and Ribbon.
  4. Expand the receipt, then Undo while that generation is still the latest transaction.

3. Make a focused direct edit

  1. Select an object and open the canvas composer.
  2. Choose Edit and confirm Selection scope.
  3. Ask for a title refinement or extra supporting detail.
  4. Inspect the changed object and any new supporting objects; explain that selection scope permits additions.

4. Retain control during a longer answer

  1. Ask for a detailed comparison.
  2. Scroll upward while output is arriving; the transcript should stop following.
  3. Use Jump to latest to rejoin the stream.
  4. Close and reopen Scapi to demonstrate that visibility and cancellation are separate.
  5. Stop if still running, and show the preserved partial answer.

5. Explain continuity honestly

  1. Complete an Ask exchange and ask a follow-up in the same session.
  2. Reload the editor and reopen Scapi.
  3. Point out the earlier answers and the “starts fresh” notice.
  4. Start a new question that states the necessary context rather than relying on restored model memory.

Demo hygiene: use fictional data and an isolated library. Do not imply that model wording, source availability, progress timing, or exact generated changes are deterministic. The examples in this document are explanatory, not captured production results.
